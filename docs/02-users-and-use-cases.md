# 02 — Users and Use Cases

## 1. User segments

### 1.1 Occasional buyer

A person who wants to avoid overpaying.

Needs:

- simple analysis,
- explanation in their language,
- price range,
- risk indicators,
- clear recommendation.

### 1.2 Private seller

A person selling an owned product.

Needs:

- recommended sale price,
- listing content,
- photo checklist,
- expected sale speed,
- price adjustment advice.

### 1.3 Professional reseller

A user who buys products for resale.

Needs:

- deal monitoring,
- profitability calculation,
- product portfolio,
- actual profit tracking,
- fast alerts,
- repeatable analysis.

### 1.4 Small business buyer

A company purchasing equipment for internal use.

Needs:

- market comparison,
- total acquisition cost,
- supplier and listing risk,
- purchase report,
- organization collaboration.

### 1.5 Procurement team

A team sourcing multiple products.

Needs:

- structured requests,
- comparable offers,
- approval flow,
- shared reports,
- audit trail,
- savings calculation.

### 1.6 Broker or sourcing specialist

A person who connects buyers and sellers.

Needs:

- sourcing requests,
- offer tracking,
- commission records,
- client reports,
- transaction status.

### 1.7 Platform administrator

Needs:

- user management,
- product catalog management,
- failed analysis review,
- manual product matching,
- price-estimate review,
- risk-rule administration,
- subscription and usage oversight,
- audit logs.

## 2. Primary use cases

### UC-01 Analyze a potential purchase

The user submits a listing and receives a purchase recommendation.

### UC-02 Analyze an owned product for sale

The user enters product details and receives recommended prices and listing content.

### UC-03 Compare multiple offers

The user compares several listings for the same product.

### UC-04 Calculate expected net profit

The user adds all acquisition and sale costs.

### UC-05 Track actual purchase and sale outcome

The user records immutable actual purchase evidence, an eight-category known/unknown cost snapshot,
and a sold, cancelled, or no-sale result against the exact current sale-portfolio event. The system
shows actual profit and sale duration only when the realized evidence chain is complete and uses
one reporting currency; otherwise it shows explicit unknowns.

### UC-06 Create a saved search

The user defines desired product, price, location, and profitability thresholds.

### UC-07 Receive a deal alert

The user receives a notification when an imported or authorized listing matches criteria.

### UC-08 Request sourcing assistance

The user submits a product sourcing request to the platform team.

### UC-09 Review uncertain product matching

An administrator confirms or corrects product identification.

### UC-10 Review suspicious analysis

An administrator inspects low-confidence or high-risk results.

## 3. User jobs to be done

### Buyer

> When I find a product listing, I want to know whether the total purchase makes financial sense so that I do not overpay or enter a bad transaction.

### Seller

> When I want to sell a product, I want a realistic pricing strategy so that I sell at the best balance between speed and price.

### Reseller

> When I evaluate many products, I want the system to rank the best opportunities so that I spend time only on deals with sufficient margin.

### Business

> When I source equipment, I want a documented comparison so that I can justify the purchasing decision and measure savings.
